# boards

Основная часть форума: доски -> темы -> посты. Контракт: `boards.v1` (`BoardService`, `ThreadService`, `PostService`).
REST для клиентов делает Envoy по аннотациям `google.api.http`, сервис отдаёт только gRPC.

HTTP `8080`, gRPC `9090` — одинаково локально и в `apps` compose. Нужны Postgres и gRPC `users`; профиль пользователя кешируется на `USERS_CACHE_TTL`.

После создания поста сервис best-effort публикует `events.v1.PostCreated` в Kafka (`KAFKA_BROKERS`, `KAFKA_TOPIC`, по умолчанию `posts.events`). Ошибка Kafka не отменяет уже созданный пост. Если `KAFKA_BROKERS` пуст, публикация отключена.

## Что внутри

- Доски создают moder и admin. Доски только для модераторов остальным не видны.
- Тема: открытая, закрытая (locked) или в архиве. Закрепление и закрытие только для модераторов.
- Пост: markdown до 20000 символов, ответ на пост вложен на один уровень. Удалённые посты остаются в списке (тело скрыто).
- Выдача по курсору (`page_size`, `page_token`), закреплённые темы всегда первыми.

## Права

| Действие | Кто |
|---|---|
| Создать доску | moder, admin |
| Читать, писать | любой залогиненный, не заблокированный |
| Тема: заголовок и категория | автор (пока тема открыта) или модератор |
| Тема: видимость, lock, pin | модератор |
| Тема: удалить | модератор, либо автор, пока нет чужих ответов |
| Пост: править | автор (пока тема открыта) или модератор |
| Пост: удалить | автор или модератор (первый пост автор отдельно не удалит) |

FAQ создают и меняют только модераторы. В закрытую или архивную тему не пишет никто.
Скрытое от читателя выглядит как «не найдено».

Личность берётся из заголовков `x-user-id` и `x-roles`, которые выставляет Envoy после проверки JWT.
Имя автора и статус (бан) сервис берёт из `users` при каждой записи, профиль кешируется на `USERS_CACHE_TTL`.

## Структура

```
cmd/boards          точка входа
internal/app        запуск и DI (app/di), миграции goose при старте
internal/transport  gRPC (protobuf <-> модели usecase), HTTP-пробы
internal/usecase    сценарии и проверка прав (boards, threads, posts), access, validate
internal/modules    boards, threads, posts: домен, repository (model, converter, pg)
internal/adapters   клиент users, Kafka-publisher событий
internal/infrastructure  config, pg (+ migrations), cursor, uuid, validate
```

## Запуск локально

1. `cp .env.example .env`, поправить адреса.
2. `go run ./cmd/boards`. Миграции применятся сами. Для уведомлений укажите `KAFKA_BROKERS`.

Тесты: `go test ./...`. Линт: `golangci-lint run ./...`.
